# P6 under `p6-zx-v2`: zero recognised, not normalised — the campaign re-baselined

**Model spend:** none.

## The decision

Run 2 of the completion campaign ended on a certified fact about the bar, not about the
candidates: under "equal up to a non-zero scalar" every diagram containing a zero-scalar
component is the zero map, so the zero diagrams of a wire signature are one semantic class of
every shape, and a rule that fires on the scalar leaves the rest of the diagram alone. No system
of local rules gives that class one normal form. `p6-zx-v1` asked exactly that, so its
completeness property was unpassable on any class that admits a spider.

`p6-zx-v2` keeps the model, the rules, soundness, termination and bounded local confluence word
for word and changes one property. A system is **complete for C(w, v, e) with zero recognised**
when every diagram of the class reduces to a normal form, a normal form is *syntactically zero* —
it contains a legless spider of phase π, the scalar 0 — exactly when the diagram denotes the zero
map, and semantically equal *non-zero* diagrams share one normal form. Zero is recognised, which
is what a decision procedure needs; uniqueness of normal forms is asked only where local rules
can deliver it. Nothing is asserted about two zero diagrams sharing a normal form.

## The verifier

One verifier, one payload switch: `zx_completeness` reads `"zero": "class"` (the v1 check, the
default, so every committed v1 evidence file re-verifies as it did) or `"zero": "recognised"`.
Two goldens pin the difference on the same R1 rule set over C(2, 1, 2): without its
zero-absorption rule R1 FAILs the v1 check on the zero pair and PASSes the v2 check; without its
two Hadamard-loop rules it FAILs the v2 check with a single-diagram witness — `Z(0)` with a
Hadamard self-loop is a normal form that denotes zero without showing it. The edit moved every zx
verifier identity; all six were re-certified and the 25 zx-backed claims re-verified with their
verdicts unchanged (57 s). `claims reverify` also listed the fifteen Lean-backed claims and
reported "no verifier available for lean" for each; `check` stays green, so this is the CLI not
resolving the built-in Lean verifier, recorded as a follow-up.

The v1 bar had hidden the real obstruction by 432 diagrams. What the best system lacks is a
rule that pushes a `Z(0)` state through a Hadamard edge into a `Z` spider — in library terms,
`copy` for a state whose colour change has not been applied (the library's `colour_change` turns
`X` into `Z`, never a `Z` state into an `X` state). The resumed campaign will show exactly this
witness to the model at every round; the copy rule in Hadamard-edge form is the obvious next
move, and JPV's bialgebra territory lies right behind it.

## Where this leaves P6

campaign is resumable under v2 from `runs/p6-completion` with the same command as before; every

ceiling is unchanged: a system passing all four checks is sound, terminating, locally confluent
at residual arity ≤ 2 within the stated depth and complete with zero recognised for the stated
bounded classes; the critical-pair lemma for star rules is still the gap to a confluence proof,
and zero recognition is a decision-procedure property, not a normal-form property.
