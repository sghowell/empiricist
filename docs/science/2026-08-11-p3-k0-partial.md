## What remains: one lemma (`case_fourCycle`, the L4 crux)

The 4-cycle case is fully set up in Lean — the cyclic label-set structure, the
4-distinctness combinatorics (`four_distinct_aux`), and **unitary row-orthogonality**
(`unitary_row_orth_aux`, which gives `⟨row_i0, row_i2⟩ = 0` for the complementary
detectors). The single unclosed hole is the **L4 crux computation**: proving the
*same* inner product is **nonzero**,

> `⟨row_i0, row_i2⟩ = x·x† + λ·λ̄ · x·Q·x† ≠ 0`,

where `x·σ_y` is a shared eigenvector of a non-identity Pauli `P` and `Q`
anticommutes with `P` (hence is off-diagonal in `P`'s eigenbasis), by a case-split
on whether the two eigenvectors are parallel (first term ≠ 0, second = 0) or
orthogonal (first = 0, second ≠ 0). Contradicting `= 0` gives `False`.

**This is a formalization-hardness boundary, not a mathematical obstacle.** The
computation is a few lines of elementary 2×2 complex linear algebra on paper; in
Lean it is stubborn because mathlib's support for concrete 2×2 complex eigenbasis
reasoning is thin, so it must be done by hand in explicit `Fin 2 → ℂ` coordinates
with fiddly off-diagonal matrix-element manipulation. The formalize loop did not
close it across **22 rounds / 3 full runs / ~$23** of live Fable, including a
micro-decomposition of the crux into eigenvector / anticommuting-off-diagonal /
inner-product-expansion / case-split sub-steps. Recorded as a partial per the M20d
plan's explicit "partial success is still recorded value" clause. The partial
`case_fourCycle` (scaffolding + the one hole) is preserved at
`2026-08-11-p3-k0-partial/case_fourCycle.partial.lean` for resumption.

connection revealed the exact remaining work, and a key subtlety:

**The engine is σ_z-specific and does NOT generalize.** For σ_x eigenvectors
`(a,a),(b,−b)`: `plainPair = twistPair = 0` — both vanish — so a naive
"general-Pauli pairing" lemma is **provably false**. The physics vectors
`xRow·σ_y` are eigenvectors of a *general* Pauli `P = pauliOf a · pauliOf b`
(`pauliOf` maps the 4 Bell labels to `{I, σ_x, σ_y, σ_z}`), so closing L4 needs the
full **basis-change machinery**:
1. **Per-Pauli diagonalizers** `B_μ` with `B_μ (pauliOf μ) B_μ⁻¹ = σ_z`, mapping
   each non-identity Pauli's eigenvectors to axis-aligned. Verified explicit
   matrices: `B_{σx} = !![1,1;1,-1]`, `B_{σy} = !![1,-I;1,I]` (both conjugate to
   σ_z AND axis-align; `B_{σz} = 1`). Extend P3Eigvec with these (fin_cases over
   BellLabel).
2. **Inner-product transform**: `⟨u,v⟩` relates to `plainPair(B_μ u, conj(B_μ v))`
   via `B_μ† B_μ = 2·1` (so `⟨u,v⟩ = ½⟨B_μ u, B_μ v⟩`). Also note the unitary inner
   product is **sesquilinear** (`U * star U` conjugates the second row) while
   `plainPair/twistPair` are bilinear — apply the engine to `conj(x₂·σ_y)`
   (`AxisAligned v ⟺ AxisAligned (conj v)`).
3. Then `case_fourCycle`: `fin_cases` on the labels → concrete `P` per branch →

**Key correction discovered (2026-08-21, by up-front numerical derivation):**
`pauli_eigvec_sesq_pairing` (not-both-zero) is **insufficient** for the final
step. The contradiction needs `⟨row_i0,row_i2⟩ ≠ 0`, and the decomposition is

> `⟨row_i0,row_i2⟩ = sesq(w₀,w₂) + c · sesq(w₀, pauliOf ν ·ᵥ w₂)`,  `c = k₀·conj(k₂)·s ≠ 0`

(x/y block split; σ_y unitary preserves `sesq`; `yRow = k·(xRow ᵥ* Kmat)`,
`Kmat = σ_y·pauliOf`). "Not both zero" is *consistent* with this sum being zero
(the terms could cancel). The correct tool is the **sum-nonzero** lemma
(numerically verified, 0/96 violations):

> `sesq u v + c · sesq u (pauliOf ν ·ᵥ v) ≠ 0`  for `c ≠ 0`, `u,v` nonzero
> eigenvectors of a non-identity Pauli, `ν` anticommuting

— true by the parallel/orthogonal **dichotomy** (eigenvalues `±1`; anticommuting
`ν` swaps the eigenspaces): in each case *exactly one* term is zero and the other
nonzero, so the sum is the nonzero one. Exact decomposition data: `ν` = the third
non-identity Pauli (neither `A` nor `C`), scalar `s = ±i`.
