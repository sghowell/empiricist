# Empiricist M7: Orchestrator, scheduler, report, CLI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tie the machine together: a resumable asyncio **orchestrator** driving the P5 campaign loop (ENUMERATE once → SEARCH + CONJECTURE waves under budget/stall control, PROVE/FORMALIZE parked at human gates), a dumb-by-design **scheduler**, the auditable **report** (spec §12 content contract), and the **CLI** (`empiricist run|resume|status|certify|gates|report`). After M7, `empiricist run P5 --live` is a real command; M9 just runs it overnight.

**Design (all pieces exist — M7 is wiring):**
- `campaign/state.py`: `CampaignState.load(run_dir)` — Ledger+Store+Registry+Population handles for a run directory (`<run_dir>/ledger.db`, `<run_dir>/store/`); create-or-resume semantics (resume = `reconcile_orphans()` + re-read spent budget; log a `resume` search_event).
- `campaign/moves.py`: the three v0 machine moves as idempotent, budgeted functions:
  - `ensure_enumerate(state, cfg) -> Artifact` — if a VERIFIED_N dataset artifact for (P5, cfg.n_max) already exists in the ledger, return it (idempotent across resume); else certify both fusion verifiers (if unstamped), run tier0_search(cfg.tier0_n)+tier1_search(cfg.tier1_n), build+ingest the dataset. THE HEAVY STEP — runs through the ledger so a kill mid-way just re-runs (ingest is atomic-ish; re-ingest of identical content collides on artifact id → catch and load existing).
  - `search_move(state, cfg, gen) -> GenerationReport` — targets = open orbits at cfg.search_target_n (from the dataset artifact's rows: open rows sorted by n then orbit_id, capped at cfg.targets_per_gen); SearchLoop.run_generation with the live-or-fake client.
  - `conjecture_move(state, cfg) -> list[Artifact]` — mine(k)+attack+submit over the dataset rows; returns artifacts (CONJECTURED and REFUTED both count as progress events; only CONJECTURED counts toward the exit criterion).
- `campaign/scheduler.py`: `Scheduler(cfg)` — weighted round-robin over ["search", "conjecture"] (ENUMERATE is a precondition, not scheduled); weights halve on a move's stall (StallDetector for search; a no-new-CONJECTURED counter for conjecture); `next_move() -> str`; `record(move, progressed: bool)`; hard stop conditions: `budget_exhausted(spent, cfg)` (max_cost_usd / max_generations) or all targets closed. PROVE: when ≥1 CONJECTURED artifact exists and no pending PROOF_CAMPAIGN gate for it → `gates.open("PROOF_CAMPAIGN", artifact_id=...)` once (parked; the scheduler skips it thereafter — spec §9's has_pending guard).
- `campaign/orchestrator.py`: `async run_campaign(run_dir, cfg, client) -> CampaignSummary` — the single loop: state=load → ensure_enumerate → loop { move=scheduler.next_move(); execute; feed stall; check budget/stop } → summary (generations, spend, conjectured count, upgrades, stop reason). All writes via the single Ledger instance (asyncio single-thread — the M1-2 single-writer discipline). KeyboardInterrupt-safe: finally-block logs a `campaign_end` event.
- `report.py` (src/empiricist/report.py): `generate(state, cfg) -> str` (Markdown) per spec §12: header (config hash, versions, total cost from runs, per-role token/cost aggregates), claims table (artifacts w/ status/status_n/coverage), per promoted claim a provenance block (evidence rows w/ verifier+version+binary_hash+verdict, certification stamps, CAS links), REFUTED section w/ counterexamples, gates section, search summary (generations, population size, exact upgrades). Pure read of the ledger — a referee can regenerate it.
- `cli.py` (src/empiricist/cli.py) + `[project.scripts] empiricist = "empiricist.cli:main"`: argparse subcommands — `run P5 --run-dir D [--live] [--max-cost X] [--max-gen N] [--tier0-n N] [--search-n N]` (default client = FakeLLMClient-refusing... no: default WITHOUT --live = "dry" mode that runs ENUMERATE + report but NO model moves, exiting with a note; --live = ClaudeCodeClient w/ preflight); `resume` (same as run — load is create-or-resume); `status` (counts by artifact status + spend); `certify` (stamp both fusion verifiers); `gates list|resolve ID --approve/--reject`; `report [--out F]`. CLI is thin — all logic in campaign/*.
- Config: extend `RunConfig` with the campaign knobs (tier0_n=9, tier1_n=7, search_target_n=8, targets_per_gen=8, conjecture_every=3, max_generations=None, max_cost_usd=None) — frozen, hashed as before.

**Trust notes:** budget check uses `ledger.spent()` (documented floor) + in-flight reservation is out of v0 (noted); the orchestrator only ever *reads* model output through the already-gated moves; F3Alarm propagates up and aborts the campaign with a durable event (already logged by the loop).

**Tests:** all offline. state create/resume round-trip (incl. orphan reconciliation observed); ensure_enumerate idempotency (second call returns the SAME artifact id; kill-and-rerun simulated by calling twice); scheduler round-robin/halving/stop conditions/gate-parking (fake gates); orchestrator end-to-end with FakeLLMClient scripted for 2 generations + 1 conjecture wave on a small (tier0_n=6) config — asserts summary counts, ledger side-effects, budget stop, resume-after-interrupt continues generation numbering; report golden-ish (contains required sections, cost figures, provenance block for the VERIFIED_N artifact); CLI smoke via subprocess-free direct main([...]) calls (argparse) for status/report/certify/gates against a prepared run dir.
