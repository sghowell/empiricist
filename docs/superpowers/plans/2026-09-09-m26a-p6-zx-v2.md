# M26a: formulation `p6-zx-v2` — zero recognised, not normalised

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the completeness bar the P6 completion campaign was measuring against — one normal form per semantic class, the zero class included, which run 2 showed no local rule system can pass — with a bar a local system can pass and a decision procedure needs: unique normal forms on the non-zero classes and a certified *recognition* of zero (the normal form of a diagram is syntactically zero, a legless π spider, iff the diagram denotes the zero map). Freeze it as `docs/problems/p6-zx-v2.md`, teach `zx_completeness` the new mode without touching the meaning of any `p6-zx-v1` evidence file, move the campaign to v2, re-evaluate the serious v1 candidates and the two groundwork systems under v2 so the ledger says where each stands, and leave the campaign resumable under v2. No model spend in this milestone.

**Architecture:** One verifier, one payload switch. `completeness.check(..., zero="class"|"recognised")`: `class` is the v1 check byte-for-byte (zero matrices of a signature are one class that must share a normal form); `recognised` groups only the non-zero diagrams into classes, requires each zero diagram's normal form to be syntactically zero and each non-zero diagram's not to be, and reports a pair witness or a single-diagram witness. The verifier reads `"zero"` from the payload (default `class`, so every committed v1 evidence file re-verifies identically) and echoes it in the details. The campaign sets `FORMULATION = "p6-zx-v2"`, sends `"zero": "recognised"`, names the step and claim `complete_nonzero_<class>` (evidence `completeness_nonzero_<class>.json`) so v2 rows never collide with v1 rows for the same candidate, and gains a `rebaseline` entry point that re-runs `evaluate` on every serious candidate in a run's history and logs a `rebaseline` event that `load_history` lets supersede the candidate's earlier evaluation (same round and slot), so a resumed run prompts from v2 outcomes and witnesses.

**Tech Stack:** Python 3.11+, numpy, the zx pack, the claims CLI (`certify-verifier`, `reverify`, `formulate`, `promote`, `check`).

**Spec:** `docs/problems/p6-zx-v2.md` (this milestone freezes it); charter §3, §5; `docs/science/2026-09-09-p6-completion-campaign.md` (run 2's finding).

## Honest ceiling

A system passing all four checks under v2 is sound, terminating, locally confluent at residual arity ≤ 2 within the stated depth, and complete with zero recognised for the stated bounded classes. Zero recognition is a decision-procedure property, not a normal-form property: two zero diagrams may have different normal forms and the claim says nothing about them. The critical-pair lemma for star rules remains the gap to a confluence proof.
